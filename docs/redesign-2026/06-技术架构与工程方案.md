## 0. 摘要

1. **【决策】架构**：在 `super-monster/wordbyword-web` 仓库内，fork SurfEnglish 的零依赖生成器思路（基线 §D、研究 03 §1）：`src/site.mjs`（`SITE`/`LOCALES`/`PAGES`/`CONTRACTS`/`ALIASES`）+ `src/data/*`（产品事实、`SIBLING`、术语表、lint 词表）+ `src/locales/*.json`（20 种语言文案）+ `src/templates/*.mjs`（纯函数模板）+ `assets/`（本地预处理好的图片）→ `node build.mjs` → `dist/` → Cloudflare Pages。Node 24，零 npm 依赖。
2. **【裁定】分支与冻结**：`main` 开发（CF 预览）、`cloudflare-deploy` 生产、其它分支即预览；冻结分支 **`legacy-pages`**（= `7a389ba`）。**在 main 推送新结构之前，必须先把 GitHub Pages 的发布源切到这个分支**（R29）。冻结是否成功按"切换前后关键 URL 的响应体 md5 与状态码一致"判定，不看 `last-modified`（R56、ENG-01，§1.2）。
3. **【决策】构建即闸门**：build 的最后一步跑全量校验：locale 侧 L-1…L-14（键一致、复数、断行记号、长度、品牌与关键词归属、术语表、产品表述 lint 等），产物侧 D-1…D-24（canonical、hreflang、**可索引性四项一致 D-20**、`_redirects` 夹具 D-12、`_headers` D-13、AVIF 结构 D-21、`<html>` 语言声明 D-22、OG 与文案一致 D-23、扩展子站两态 D-24 等），共 38 项。任何 error 都让 `node build.mjs` 以非 0 退出，CF 部署随之失败，生产环境保持上一版（§3.7）。
4. **【决策】指纹与缓存**：CSS、JS、图片、OG 图、徽章统一走 `/assets/…<hash>.<ext>`，设 `immutable` 一年；HTML 沿用 CF 默认的 `max-age=0, must-revalidate`。`_headers` 的 `/*` 规则里**不写** `Cache-Control`，**整个文件不出现** `Content-Language`（R47），`X-Robots-Tag` 只出现在 pages.dev 主机规则里（§3.6.4）。
5. **【裁定】图片**：裁切 preset、画质参数、CSS 机身按文档 05；脚本名、目录、指纹路径按本文（R8）。`scripts/images.mjs` 在 macOS 上运行：**裁切与偶数宽高修正在 node 中完成**（解码 PNG → 裁切 → 编码），`sips` 只做 sRGB 转换、缩放与 AVIF + JPEG 编码（R79），产物与 `images.json` 一起提交；`scripts/check-images.mjs` 做 AVIF 结构校验（零依赖，构建机也跑，D-21）和 Chrome 实际解码的 alpha 抽样（仅 Mac），二者共同构成闸门，sips 回解只作辅助（R79 修正 R58；ENG-05）。CF 的 Linux 构建机只做复制和指纹（§7）。
6. **【裁定】`_redirects` 与契约 URL**：`_redirects` 的唯一规格是文档 02 §5.2 的映射表与夹具（R54）。生成器按 A–D 组（及实验组 L、C）逐条产出，默认 **67 条静态、7 条动态**，D-12 拿 `scripts/fixtures/redirects.default.txt` 逐行比对（§3.6.3）。契约 URL 首选 C-1（`/legal/<slug>/` 正文 + 200 代理回 `/privacy.html` 等），canonical 指向契约 URL，`/legal/*` 不加 noindex（R48）；preview 实测不通过的契约逐个退回 C-2（§9）。
7. **【裁定】统计**：GA4 `G-QS1CJY8YWL` 由 `SITE.gaId` 统一输出（替代 26 处硬编码，F9）。`analytics.js` 修复 Chrome 商店识别（`js/analytics.js:86-87`），新增 `faq_toggle`、`language_switch`（带 from/to，R38）、`surfenglish_promo_view`（只给落点 ①，R3）。SE 推荐的 label 按文档 04（`card_*`、`faq_site`、`footer_site`、`about_*`，R3）；App Store `ct` **只按落点、不按 locale**：WBW 自身 `wbw-header`/`wbw-hero`/`wbw-pricing`/`wbw-cta`/`wbw-footer`/`wbw-about`/`wbw-ext`/`wbw-sab`，SE 链接 `wbw-card`/`wbw-about`（R3、R55，§8.3）。Consent Mode 预留 `SITE.consentMode`，取值待 H6。
8. **【裁定】应急公告**：构建期从 `src/notice.json` 渲染成 `<div data-nosnippet>`，放在正常文档流中。应急发布**从生产分支拉 hotfix 分支**提交并部署，再合回 main，不得从 main 直接部署到生产（R57、ENG-04，§8.5）。公告开启时只隐藏落点 ①（R35）。
9. **【裁定】切换**：严格按"先在 CF 绑定域名 → 再改 `www` CNAME"执行。T0 目标窗口 2026-11-17 ～ 11-26（预期 11-25），避开 12-18 ～ 01-04（R23，排期以文档 07 为准）。DNS 层回滚到 GitHub Pages 的截止时间 = **T0 当时 GitHub Pages 证书的 notAfter**（T-1 实测记录，不写死 12-23，R23）。GitHub Pages 的下线顺序与防子域接管措施见 §10。
10. **工作量**：排期与估时以文档 07 为准（R23）。§12.1 保留按模块拆分的工程估算，作为 07 的输入：约 25 人日，加 20% 缓冲约 30 人日。不含 19 种语言的文案撰写与翻译（文档 08）、母语审校（R36）和视觉设计稿本身。

### 1.2 分支模型【决策】

| 分支 | 作用 | 谁会构建 | 约束 |
|---|---|---|---|
| `main` | 日常开发 | CF preview + `check.yml` | 合并前必须本地 `npm run check` 通过 |
| 功能分支 `feat/*` | 较大改动 | CF preview（每个分支有固定别名 `<branch>.<project>.pages.dev`）| — |
| `cloudflare-deploy` | 生产发布：`git push origin main:cloudflare-deploy`（与 SE `DEPLOY.md` 一致） | CF production | 只允许快进；开 GitHub 分支保护 |
| `hotfix/notice-<日期>` | 应急公告专用：从 `cloudflare-deploy` 拉出，只改 `src/notice.json`（R57，§8.5） | CF preview + `deploy-manual.yml` 部署到生产 | 部署后快进合入 `cloudflare-deploy`，再合回 `main` |
| `legacy-pages`（新增） | 冻结的旧站，等于 `7a389ba`（若先执行文档 07 M0-09 的止损改动〔H18〕，则为该止损提交），作为 GitHub Pages 的发布源和 DNS 回滚目标 | GitHub Pages（classic，Jekyll）。CF 的 preview **排除**该分支（§10.1） | **禁止推送**；GitHub Pages 下线后转成 tag `legacy-site-2026-08-23` 并删除分支 |

**关键顺序【裁定 R29】**：现在 GitHub Pages 是"从 main 分支部署"（F1、研究 09 §1.1）。新结构推上 main 后，根目录不再有 `index.html`，Jekyll 会把 `README.md` 当首页发布，线上会立刻坏掉；DNS 切换之前的回滚目标也就没了。所以：

1. 记录冻结前基线（R56、ENG-01）：
   ```bash
   B=https://www.word-by-word.app
   for p in / /ja-top.html /privacy.html /support.html /chrome-extension/privacy.html; do
     printf '%s %s %s\n' "$p" "$(curl -s -o /dev/null -w '%{http_code}' "$B$p")" "$(curl -s "$B$p" | md5)"
   done > legacy-before.txt        # 例如 / 为 200，content-length 11664（F1）
   ```
2. `git branch legacy-pages 7a389ba && git push origin legacy-pages`。
3. GitHub → Settings → Pages → Source 选 `legacy-pages` / `(root)`，保存，等待约 1 分钟重建。重跑第 1 步的命令输出到 `legacy-after.txt`，`diff legacy-before.txt legacy-after.txt` 无差异即通过。**`last-modified` 和 `ETag` 会变成新的部署时间，这是 GitHub Pages 每次部署的正常行为，不代表冻结失败**（ENG-01 实测：全站文件的 `last-modified` 都是部署时刻 2026-08-23 08:14:40 GMT，与各文件的提交时间无关）。
4. 上一步通过后，main 才能推送删除旧文件的提交；`docs/` 也不例外（R30、H10，§2.1）。

### 1.3 工程原则

- 零依赖：build、check、serve 只用 Node 内置模块。可选工具（wrangler、Lighthouse）只通过 `npx` 在开发机上临时调用，不写进 `package.json` 的依赖。需要的第三方数据（OpenCC 简体字表等）以数据文件形式 vendor 进仓库并注明许可证（§4.3）。
- 单一事实源：产品事实（额度、价格、语言数、版本）只写在 `src/data/product.json`（取自 F13–F18），文案通过 `{占位符}` 引用；SE 推荐的配置只写在 `src/data/sibling.mjs` 的 `SIBLING`（文档 04 §3.7）；`_redirects` 只由 `LOCALES`/`CONTRACTS`/`ALIASES`/`SITE.redirectFlags` 生成，并以文档 02 §5.2 的夹具为准（R54）。
- 无 JS 也完整可用：所有内容、链接、推荐区块、公告都由构建期生成成静态 HTML（F10、研究 04 §4.2）。
- 不照抄 SE 的缺陷（研究 03 §1.13、F23）：合法的 `applicationCategory`；`og:locale` 使用 `ll_CC`；控制标题长度；先给图片加指纹再设长缓存；404 不写 canonical；locale 缺失时不再整文件回退成英文。
- 原型只是参考（R30）：`prototype/` 的 head 带 `noindex, nofollow`，模板移植时不得带入（R49，D-20 兜底）。

各字段的语义：
- `indexable`：布尔值或函数。决定 robots meta（`index,follow,…` 或 `noindex,follow`）、是否输出 canonical、是否进 sitemap、是否进入 hreflang 簇；四者由同一个值驱动，D-20 校验一致（R49）。
- **hreflang 簇**【决策，ENG-14】：簇的成员 = 同一页面键下 `indexable` 为真的已生成路由。成员 ≥ 2 时，每个成员输出全部成员（含自身）、附加码和 x-default（有 en 成员时）；成员只有 1 个时不输出 hreflang（文档 02 §6.1 HL-1…HL-4）。因此 S0 状态下扩展页不输出 hreflang（v1.0 的 `cluster` 字段删除，由页面键 `id` 代替）。
- `publicUrl`：对外 URL。canonical、sitemap、站内链接都用它。契约在 C-2 模式下它变成 `/privacy` 等。
- `sibling`：`'full'` = 首页落点 ①②④（zh-Hans 为 ②④，R42）；`'about'` = ④⑤；`'footer-only'` = 只有 ④ 页脚家族链接（基线 §F）。
- `sources`：lastmod 的计算依据（§3.6.1）。**不包含** `build.mjs`、`layout.mjs` 和 CSS，避免全站 lastmod 一起跳（研究 03 §1.6）。about 的 sources 含 `en.json`，所以 en 文案的任何改动都会推动 about 的 lastmod，这是"键级来源追踪"成本太高之下的可接受近似。
- `updated`（legal）：页面 "Last updated" **只**取源文件首行的人工维护日期，不取 git 日期。否则迁移提交当天就会把隐私政策的更新日期改成迁移日，等于对外声明"政策已更新"（ENG-14）。

### 3.4 渲染流程（伪代码）

```js
// build.mjs
const t0 = performance.now();
const issues = new Issues();                        // {error[], warn[]}
const cfg = await loadConfig();                     // SITE, LOCALES, PAGES, CONTRACTS, ALIASES, product, SIBLING, notice, glossary, claims, keywordMap

rmSync(DIST, { recursive: true, force: true }); mkdirSync(DIST);

copyDir('public', DIST, { skipDotfiles: true });    // 先复制 public/（ENG-16）；public/ 下有 _headers/_redirects 时 D-14 报 E
const assets = emitAssets(cfg, issues);             // css/js 合并+指纹；images.json 核对 → dist/assets/img；og（核对 og.json）；badges
const routes = expandRoutes(cfg, strings);          // [{page, locale, outFile, url, publicUrl, indexable, canonical}]

for (const r of routes) {
  const ctx = makeCtx(cfg, strings, assets, r, routes);   // t, alternates, links, img(), fill(), seMode, year…
  writeFile(join(DIST, r.outFile), TEMPLATES[r.page.template](ctx));
}

const redirects = buildRedirects(cfg);              // §3.6.3（文档 02 §5.2 夹具）
writeFile('dist/_redirects', redirects.text);       // 生成物最后写，不会被 public/ 覆盖（ENG-16）
writeFile('dist/_headers',   buildHeaders(cfg));    // §3.6.4
writeFile('dist/sitemap.xml', buildSitemap(routes, cfg));   // §3.6.1
if (cfg.SITE.legacySitemap) writeFile('dist/sitemap-legacy.xml', buildLegacySitemap(redirects));
writeFile('dist/robots.txt', buildRobots(cfg));
if (cfg.SITE.indexNowKey) writeFile(`dist/${cfg.SITE.indexNowKey}.txt`, cfg.SITE.indexNowKey);

writeJson('.cache/routes.json', routes.map(publicView));       // verify-deploy.sh 读取（文档 02 §5.2.4、§5.5 第 6 条）
writeJson('.cache/redirects.json', redirects.rules);
writeJson('.cache/contracts.json', contractsView(cfg));      // contract-test.sh 读取（§9.3）

if (process.argv.includes('--pseudo')) pseudoLocaleScan(cfg, issues);      // D-15（b）：伪 locale 渲染找硬编码字符串

```

`expandRoutes` 的规则：`locales:'*'` 展开为全部 `publish:true` 的 locale；显式列出的 locale 只取 `publish:true` 的那些。`outFile` 由 `path(l) + 'index.html'` 或 `file` 得到。`publicUrl = page.publicUrl ?? '/' + path`；`indexable = typeof page.indexable === 'function' ? page.indexable(l) : page.indexable`；只有 `indexable` 的路由才有 `canonical = absUrl(publicUrl)`（R49）。`npm run check` 默认带 `--pseudo`；CF 构建不带，以控制构建时长。

#### 3.6.1 sitemap.xml

- 只列 `indexable` 路由的 `publicUrl`（绝对地址）：20 个首页、`/about/`、`/privacy.html`、`/support.html`，S0 共 23 条；S1 时再加 `/chrome-extension/`、`/zh-hans/chrome-extension/`、`/chrome-extension/privacy.html`，共 26 条（文档 02 §2.1）。`/legal/*`、404、所有跳转源都不列（D-20）。

- `lastmod`：取 `git log -1 --format=%cs -- <sources>`；工作区有未提交改动时取构建日（沿用 SE `:77-93`）。**新增**：如果 `git rev-parse --is-shallow-repository` 返回 `true`，就**整体省略 lastmod** 并告警（Google 只采信准确的 lastmod，研究 06 §8）。CF 构建机的克隆深度已由 M1-03 实测为 **1**（浅克隆）。同一次实测证明构建内 `git fetch --unshallow` 可行（约 2 s），因此构建在 `CF_PAGES` 环境下先补全历史，失败时才走上面的"省略 lastmod 并告警"（`ops/decision-log.md` M1-03 第 8 项）。CF 构建环境的 origin 地址内嵌访问令牌，构建不得打印或写出 remote。`check.yml`、`deploy-manual.yml` 都用 `fetch-depth: 0`，保证应急发布不会让生产 sitemap 丢失 lastmod（ENG-04、SEO-10）。

#### 3.6.3 `_redirects`（按文档 02 §5.2 生成）【裁定 R54】

`_redirects` 内容的**唯一规格**是文档 02 §5.2：开关表（§5.2.1）、默认夹具（§5.2.2）、开关增量（§5.2.3）、请求级用例（§5.2.4）。v1.0 的"6 + 42 + 1 = 49 条"生成器**已被 R54 取代**：它缺少 D 组别名、契约尾斜杠变体和 `/index.html` 规则，也与文档 07 M1-06 的验收数字不符（SEO-14、ENG-03）。

```js
export function buildRedirects({ SITE, LOCALES, CONTRACTS, ALIASES }) {
  const st = [], sp = [];                                    // 静态段 / splat 段（splat 一律放最后，文档 02 §5.3 第 2 条）
  const add = (seg, id, from, to, code) => seg.push({ id, from, to, code });
  const F = SITE.redirectFlags;
  const mode = (c) => (typeof SITE.contractMode === 'string' ? SITE.contractMode : SITE.contractMode[c.id] ?? 'proxy');
  const byCode = (code) => LOCALES.find((l) => l.code === code);
  const home = (l) => (l.path ? `/${l.path}/` : '/');
  const dest = (l, splat = false) => (l.publish                                    // publish:false → 302 到 /（§5.2.3）
    ? { to: home(l) + (splat ? ':splat' : ''), code: 301 } : { to: '/', code: 302 });

  // A：契约 200 代理在最前（CF 首条匹配）；C-2 的契约按 §5.2.3 增量处理
  CONTRACTS.forEach((c, i) => { if (mode(c) === 'proxy') add(st, `A${i + 1}`, c.public, c.internal, 200); });
  CONTRACTS.forEach((c, i) => {
    if (mode(c) === 'proxy') { add(st, `A${4 + 2 * i}`, c.bare, c.public, 301); add(st, `A${5 + 2 * i}`, c.bareSlash, c.public, 301); }
    else add(st, `A${5 + 2 * i}'`, c.bareSlash, c.bare, 301);               // C-2：/x.html → /x 由 CF 自动 308
  });
  if (F.experimentL) CONTRACTS.forEach((c, i) => { if (mode(c) === 'proxy') add(st, `L${i + 1}`, c.internal, c.public, 301); });
  // B：英文首页重复
  if (F.indexHtmlRule) { add(st, 'B1', '/index.html', '/', 301); add(st, 'B2', '/index', '/', 301); }
  add(st, 'B3', '/en-top.html', '/', 301); add(st, 'B4', '/en-top', '/', 301);
  // C：旧扁平语言页（en 以外，按 LOCALES 顺序与 legacy 顺序；.html 与无扩展名各一条）
  let n = 0;
  for (const l of LOCALES) if (l.code !== 'en') for (const old of l.legacy) {
    const { to, code } = dest(l);
    add(st, `C${String(++n).padStart(2, '0')}`, `/${old}-top.html`, to, code);
    add(st, `C${String(++n).padStart(2, '0')}`, `/${old}-top`, to, code);
  }
  // D：别名（静态 /x、/x/ 在前；splat /x/* 在最后）
  let d = 0;
  for (const a of ALIASES) { const { to, code } = dest(byCode(a.to));
    add(st, `D${String(++d).padStart(2, '0')}`, `/${a.from}`, to, code);
    add(st, `D${String(++d).padStart(2, '0')}`, `/${a.from}/`, to, code); }
  // X（实验组 C，静态）：hreflang ≠ path 的 locale
  const cased = LOCALES.filter((l) => l.publish && l.path && l.hreflang !== l.path);
  if (F.experimentC) cased.forEach((l, i) => {
    add(st, `X${2 * i + 1}`, `/${l.hreflang}`, home(l), 301); add(st, `X${2 * i + 2}`, `/${l.hreflang}/`, home(l), 301); });
  for (const a of ALIASES) { const { to, code } = dest(byCode(a.to), true);
    add(sp, `D${String(++d).padStart(2, '0')}`, `/${a.from}/*`, to, code); }
  if (F.experimentC) cased.forEach((l, i) => add(sp, `X${2 * cased.length + i + 1}`, `/${l.hreflang}/*`, `${home(l)}:splat`, 301));

  const rules = [...st, ...sp];
  return { rules, static: st.length, dynamic: sp.length,
           text: rules.map((r) => `${r.from}  ${r.to}  ${r.code}`).join('\n') + '\n' };
}
```

- 默认开关下输出 **67 条静态（A 9 + B 4 + C 40 + D 14）+ 7 条动态（D splat）**【事实：上面的代码已在本机 Node 24.14.1 上执行，默认输出与文档 02 §5.2.2 夹具的 74 行逐行（含 id 与顺序）相等；各开关组合的条数与文档 02 §5.2.3 条数表一致，实验组 L、C 的插入位置与 C-2 的 `A5'` 增量也符合】；+L 为 70/7，+C 为 73/10，L+C 为 76/10；每个契约降为 C-2 时 −2，`indexHtmlRule=false` 时 −2（文档 02 §5.2.3 条数表）。远低于 2,000/100 的上限（F24）。v1.0 与文档 07 M1-06 写的"62/7"是计数错误（C 组实际 40 条），以文档 02 为准。
- 【决策】不使用 `/:lang-top.html` 这类占位符（研究 09 §3.4 的三条理由；文档 02 §5.3 第 1 条）。`/backup/*`、`/README.md`、旧图片/CSS/JS 不写规则，直接返回 404（基线 §C；文档 02 §5.2.2 E 组）。
- 夹具：M1-04/M1-06 把文档 02 §5.2.2 原样转写为 `scripts/fixtures/redirects.default.txt`、§5.2.4 转写为 `scripts/fixtures/requests.tsv`（设计文档默认不入库，R30）。D-12（g）用它逐行比对；两者任一改动必须在同一次变更中同步另一方。
- build 同时输出 `.cache/redirects.json`（开关生效后的规则，含 id），供 `verify-deploy.sh` 生成断言（§11.4）。

#### 3.6.4 `_headers`

```
/*
  X-Content-Type-Options: nosniff
  X-Frame-Options: DENY
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=(), browsing-topics=()
  Strict-Transport-Security: max-age=31536000

/assets/*
  Cache-Control: public, max-age=31536000, immutable

/icons/*
  Cache-Control: public, max-age=604800

/favicon.ico
  Cache-Control: public, max-age=604800

https://:project.pages.dev/*
  X-Robots-Tag: noindex

https://:version.:project.pages.dev/*
  X-Robots-Tag: noindex
```

- 【决策】HTML、sitemap、robots 不写 `Cache-Control`，沿用 CF 默认的 `public, max-age=0, must-revalidate`（研究 09 §3.2）。`/*` 块里**绝不能**出现 `Cache-Control`：CF 文档写明 "If a header is applied twice in the _headers file, the values are joined with a comma separator"，这会让 `/assets/*` 得到互相矛盾的指令。如需取消某个头，用 `! Header` 语法。【需实测】在 preview 上执行 `curl -sI` 查看 `/assets/*` 的最终 `Cache-Control`。
- 【裁定 R47】**不输出 `Content-Language` 头**，`_headers` 中不得出现这个名字（D-13）。同样因为逗号拼接：若用 `/*` 给 en 设值，`/ja/` 会返回 `en, ja`（SEO-04、ENG-07）。语言声明只靠 `<html lang>` 和 `<meta http-equiv="content-language">`（§5.1.1）。
- 【决策，SEO-06】`X-Robots-Tag` 只出现在两条 pages.dev 主机规则里（CF 文档给出的写法，文档 02 §6.8），任何路径规则都不得携带；`/legal/*` 也不加（R48）。验收时确认正式域名**没有** `X-Robots-Tag`（§11.4 组 5）。preview 子域是否被 CF 默认加 noindex【需实测】；第二条规则保证即使没有也被覆盖。
- HSTS：`.app` 已在 HSTS 预加载列表（F6），这个头只是冗余兜底。**不加 `includeSubDomains`**，避免把策略扩散到 `api.`、`backend-test.`。
- CSP：本期不加（站内有内联 gtag 和 JSON-LD）。P2 可以由 build 计算内联脚本的 sha256，生成 `Content-Security-Policy`，放行 `www.googletagmanager.com` 和 `*.google-analytics.com`（研究 09 §5.12）。

#### 3.6.5 404

`dist/404.html` 必须存在：如果根目录没有 404.html，CF Pages 会按 SPA 处理，把未知路径以 200 返回首页，构成软 404【事实，CF 文档；D-14 校验】。Phase 1 只做 en（R21）：`noindex`、无 canonical、无 hreflang；英文正文，加 20 种语言首页的原生名称链接（带 `lang`、`hreflang`，`data-ga-label="404:<code>"`）和"回到首页"链接。本地化 404（`/<locale>/404.html`）是 M4 可选项，前提是 M1-03 证实 CF 支持就近查找嵌套 404（文档 02 §6.9）。

## 4. locale JSON schema

### 4.1 类型、标记与长度约定

| 类型 | 允许的标记 | 渲染 |
|---|---|---|
| `text` | 无（全部转义）；可以用 `{占位符}` 与复数 | `esc(fill(s))` |
| `kwtext` | `[[关键词]]`（仅限下列字段）+ `{wbr}`（仅 CJK）+ 占位符 | `mk(fill(s))`；输出到 title、meta、JSON-LD、alt、aria-label 时用 `plain()` |
| `rich` | `**强调**`、`[文本](@ref)`、空行分段 + 占位符 | `rich(fill(s))`；ref 白名单：`@appstore` `@se-site` `@se-appstore` `@se-maker` `@support` `@support-mail` `@privacy` `@about` `@chrome` `@home` `@features` `@faq`（`@home`、`@se-maker`、`@support-mail` 由文档 08 S16 增补） |

- **荧光笔 `[[ ]]`**【裁定 R65】：只允许出现在 `hero.title`、`chromeExtension.hero.title`（页面 H1，各恰好 1 处）和 `meta.ogHeadline`（OG 图标题，至多 1 处）。其它 section 标题不再加黄块，改用排版层级、红色引用条或速度线 eyebrow（文档 05）。v1.0 允许的 `features[].title`、`languages.title` 中的 `[[ ]]` 由 L-7 报 E，文档 08 需按 R65 删除标记（原型 D7 已经只保留 `<mark>`、不显示黄色）。
- **断行记号 `{wbr}`**【裁定 R61、I18-03】：CJK 标题的断行提示写成 `{wbr}`，构建时转成 `<wbr>`；在 title、meta、OG、JSON-LD、alt、aria-label 中由 `plain()` 剥除。全角 `｜` 只作 CJK title 与 JSON-LD name 的分隔符（文档 03 §3.1），**不再**作断行标记（原型 D16 的写法作废）。允许 `{wbr}` 的"标题类字段"：`hero.title`、`featuresIntro.title`、`features[].title`、`gallery.title`、`languages.title`、`pricing.title`、`sibling.card.title`、`faq.title`、`cta.title`、`chromeExtension.hero.title` 及各按钮文字。适用 locale 为 ja、zh-Hans、zh-Hant（`script='cjk'`）；ko 靠空格断行，不需要。是否给 zh-Hans/zh-Hant 标注、还是改用 `word-break: normal; text-wrap: balance`，由文档 05 §3.5 决定；工程两种都支持。
- **复数**【裁定 R62、I18-02】：数值占位符后面接可数名词时，写成最小 ICU 复数语法：`{targetLanguages, plural, one{# язык} few{# языка} many{# языков} other{# языка}}`。构建时用 `new Intl.PluralRules(code).select(n)` 选择分支，`#` 替换为本地化数字。ru、uk、pl、ar 必须使用（L-12）；其它语言可以使用。【事实，本机 Node 24.14.1 实测】`Intl.PluralRules('ru'/'uk').select(21)` 为 `one`，pl 的 21 为 `many`；ar 的 5、10 为 `few`，20、21、50 为 `many`，100、500 为 `other`。
- **价格**【决策，I18-02】：`{plus.priceUS}` 不再是写死的 `"$3.99"`，而是由 `product.json` 的 `priceUSD: 3.99` 经 `Intl.NumberFormat(code, { style:'currency', currency:'USD' })` 输出（实测：en/ja `$3.99`、zh-Hans `US$3.99`、de `3,99 $`、fr `3,99 $US`、pt-BR `US$ 3,99`）。文案仍需注明"美区价格"。
- `@se-appstore` 在 zh-Hans 中解析为 `null`，此时链接文字按纯文本输出（D-11 兜底）。
- **长度度量**【裁定 R14】：按文档 03 §3.1 的分文字类型度量（`lib/text-length.mjs`）。拉丁、西里尔、阿拉伯文按字素数；中日韩按全角宽度（全角、谚文记 1，半角记 0.5）；泰文、天城文按去掉组合符号后的可见字符数。下表的长度约束沿用 v1.0 的数值时，单位换算为：v1.0 的 `N wu` ≈ 拉丁 N 字符 ≈ 中日韩 N/2 全角宽度。

### 4.4 回退与发布策略【决策】

- 不做逐键回退成英文：已发布的 locale 缺键时构建直接失败（L-1）。文案还没到位的语言设为 `publish:false`，旧 URL 302 到 `/`（§3.2）。
- 可以分批上线：首批上线的语言集合由文档 07 §4.4 决定；工程上支持"20 个语言一次性上线"或"分批 publish"。
- `en.json` 是结构母本。新增键时先改 en，再跑 `npm run check:keys` 列出其它 19 个文件缺少的键，交给翻译。
- 【裁定 R59】en 字符串冻结（tag `strings-v1`）放在 en 的全部模板完成之后（文档 07 M2-03/M2-05），并以 D-15（b）"伪 locale 渲染 0 个硬编码界面字符串"为前提（ENG-11）；冻结后新增的键按批次走 `check:keys`，每个 locale 最多再审一轮。

## 6. 前端 JS

### 6.1 原则【决策】

- 只做渐进增强。**JS 失败、被拦截或用户关闭 JS 时，页面完整可用**：内容可见、链接可点、语言菜单和手机导航靠 `<details>` 原生展开、FAQ 靠原生 `<details>`、样张显示终态。
- 不用框架、不用模块加载器、不用 polyfill；目标为支持 IntersectionObserver 的浏览器，不支持时直接显示终态。
- 不插入、不移除任何影响布局的节点（CLS 目标 ≤0.05）。
- 【裁定 R7】**不做滚动渐入 reveal**。动效只限 hero 样张与微交互，全部受 `prefers-reduced-motion` 约束。

### 6.2 模块

| 模块 | 行为 | 要点 |
|---|---|---|

```js
// scripts/images.mjs 片段（零依赖；scripts/lib/png.mjs 移植原型 tools/png.mjs 的 decodePNG / encodePNG，参照原型 build-images.mjs 的 cropSRGB()）
import { decodePNG, encodePNG } from './lib/png.mjs';
function cropPNG(inFile, { x, y, w, h }, outFile) {          // 第 3 步；第 5 步是 x = y = 0 的特例
  const img = decodePNG(readFileSync(inFile));              // → { width, height, data: RGBA8 }
  if (x < 0 || y < 0 || x + w > img.width || y + h > img.height)
    throw new Error(`crop ${x},${y} ${w}x${h} outside ${img.width}x${img.height}: ${inFile}`);   // §7.5 第 2 条
  const out = Buffer.alloc(w * h * 4);
  for (let r = 0; r < h; r++)                                 // 逐行拷贝 RGBA
    img.data.copy(out, r * w * 4, ((y + r) * img.width + x) * 4, ((y + r) * img.width + x + w) * 4);
  writeFileSync(outFile, encodePNG(w, h, out));
  return { w, h };
}
// 裁切框（文档 05 §7.1；P 为 preset 整屏区）：
//   整屏条目  cut = round(54 / 874 × P.h)；{ x: P.x, y: P.y + cut, w: P.w, h: P.h − cut }
//   节选条目  y0 = P.y + round(region.y × P.h)；{ x: P.x, y: y0, w: P.w, h: min(round(region.h × P.h), P.y + P.h − y0) }
//   crop 条目 直接用源像素矩形（如 se/common/games 的 0,112 720×792）
//   偶数修正  { x: 0, y: 0, w: W − W % 2, h: H − H % 2 }，W、H 为第 4 步输出的实际尺寸
```

- **为什么裁切不用 sips**【事实，原型 README G6；R79】：本机实测 `sips -c` / `--cropToHeightWidth … --cropOffset` 有两个静默错误：偏移为 `0 0` 时被忽略、退回居中裁切；裁切框下边恰好贴着图片底边时（raw preset 去状态栏后为 0,162 1206×2460，源图 1206×2622）直接返回未裁切的原图，都不报错。v1.1 本节第 2 步用于 raw preset 时（偏移 0 0；去状态栏后裁切框贴底）与第 4 步的偶数修正（`--cropOffset 0 0`）正好落在这两种情形，已改为 node。原型 `build-images.mjs` 的 `cropSRGB()` 已是 node 裁切，但 `resampleEven()` 的偶数修正仍调用 `sips -c … --cropOffset 0 0`（本机产出的 AVIF 全部为偶数，但依赖的正是上述不可靠行为），生产按第 5 步改为 node。sips 保留的职责只有：解码与 P3 → sRGB、`--resampleWidth` / `-Z` 缩放、AVIF / JPEG / PNG / ICO 编码。
- **为什么必须修正为偶数**【事实，原型 K1、ENG-05】：`sips` 遇到边长超过 1024px 的 AVIF，会写成 512px 分块的 grid；Chrome（libavif）渲染宽或高为奇数的 4:2:0 grid AVIF 时，整张图是**全透明**的，页面上表现为白板。v1.0 本节的示例命令（裁 1402×2892 → `--resampleWidth 720` → AVIF q60）正好产出这种图：ENG-05 复现得到 84,970 B，文件中含 `grid` 项，`ispe` 为 512×512（分块）与 720×1485（奇数高）。所以第 5 步不可省略，并由 §7.5 的两层校验兜底。
- **透明底**：按文档 05 的 preset 只裁屏幕区，输出不带 alpha，也就没有 v1.0 担心的"JPEG 回退把透明区压成白色"的问题。若有图确需保留透明（如图标），`"alpha": true`，JPEG 回退会把透明区压成白色（采样角落像素为 `#FFFFFF`），只影响不支持 AVIF 的旧浏览器（WBW 目标用户为 iOS 18+，Safari 16.4 起支持 AVIF，F13）。
- 不输出 WebP：本机没有工具，引入工具就是新增依赖（F33）。

### 7.5 校验（`images.mjs` 内置 + `scripts/check-images.mjs`）

`images.mjs` 每次运行都做：
1. 源存在，且不在 `deny` 列表中。
2. 裁切框（`preset` 去状态栏、`region`、`crop`）在源图尺寸之内，由 node `cropPNG()` 断言（R79）。
3. 输出宽高与期望一致，宽高比误差不超过 0.5%，**宽和高都是偶数**（R8）。
4. 每个变体不超过 `budget`，超出报 W。
5. 同一 key 的所有变体格式齐全。
6. 运行结束后列出 `assets/img` 中没有登记的孤儿文件，加 `--prune` 参数时删除。
7. 运行环境不是 macOS，或 `sips --formats` 中没有 `avif Writable` 时，直接退出并提示。

`scripts/check-images.mjs`【裁定 R79（修正 R58），按 ENG-05 落实】分两层，**两层共同构成闸门**：

| 层 | 何时跑 | 做法 | 失败条件 |
|---|---|---|---|
| ① 结构校验 | 每次 build（D-21，Linux 构建机也跑）与 `npm run images:check` | `lib/avif.mjs` 零依赖解析 `ftyp/meta/iinf/iprp/ipco/ispe`：读出主图宽高与是否为 `grid` | 宽或高为奇数；与 `images.json` 不一致 |
| ② 渲染校验 | 仅 Mac：`npm run images:check -- --render`，`npm run images` 结束时自动执行；M2-09 验收必须通过 | 用 `scripts/serve.mjs` 在 `127.0.0.1` 起本地服务（必须走 http；`file://` 下 canvas 会被污染），Chrome headless 打开检查页：`--headless=new --dump-dom --virtual-time-budget=15000 http://127.0.0.1:<port>/__imgcheck.html`。检查页对每张 AVIF 执行 `img.decode()`，画到 canvas，读取 5 个采样点（中心与四角内缩 10%）的 alpha，并把整图缩到 32×32 统计透明像素比例，结果写进 `<pre id="out">` 的 JSON，脚本从 dump 出的 DOM 中读取 | `alpha:false` 的图：任一采样点 alpha 为 0，或透明像素比例 > 1%；`alpha:true` 的图：5 个采样点全为 0 |

- 【裁定 R79】R58 提到的"用 `sips -s format png` 回解 AVIF 再读 alpha"保留为 `--sips` 辅助模式，**不作为闸门**：缺陷出在 Chrome/libavif 对奇数尺寸 grid 的处理，`sips`/ImageIO 解码复现不出来（ENG-05；原型 G5 实测坏图 sips 回解 1.69% 透明、Chrome 回解 100% 透明），只有 Chrome 实际解码才能拦住。R79 已据此修正 R58 的字面要求（一致性审计 L5 关闭）。
- 原型 v1.0 README 中"`check` 时逐图解码复核"的说法已失效：原型 v1.1 的 `tools/avif-check.mjs` 已实现结构 / sips / Chrome 三层校验（原型 README §2 R58 行、§5 G5、§6 K2），可作为本节①②两层的参考实现直接移植（其 `chromeAlpha()` 用 DevTools 协议读 canvas 像素，与上表 `--dump-dom` 的读取方式等价，二选一）；sips 层只作提示（G5 实测其复现不了白板问题）。

### 7.6 运行方式

`npm run images` 只在维护者的 Mac 上运行，产物提交入库，CF 构建机不运行它。约 60 个派生文件（原型实测 64 个，README §2），单张转换约 0.1 秒，全量加渲染校验不到 1 分钟。

## 9. 契约 URL 的实现与测试

契约 URL 的规格（期望值、判定表、实验组 L）以文档 02 §5.4 与 §5.2.4 Q01–Q16 为准；本节给出实现与正式脚本。

### 9.1 C-1（默认：`SITE.contractMode='proxy'`）

- 正文输出到 `dist/legal/{privacy,support,extension-privacy}/index.html`；`dist` 中**不出现** `privacy.html`、`support.html`、`chrome-extension/privacy.html`，否则会触发 CF 的自动 308（D-14）。
- `_redirects` 的 A 组（§3.6.3，文档 02 §5.2.2 A1–A9）：3 条 200 代理，再加 6 条无扩展名与尾斜杠变体到 `.html` 的单跳 301（旧站这些变体也返回 200，F5）。
- 代理目标**必须带尾斜杠**（`/legal/privacy/`）。如果写成 `/legal/privacy`，CF 可能先对目标做一次 308，再把 308 暴露给客户端【需实测】。
- 页面 canonical 写 `https://www.word-by-word.app/privacy.html`。`/legal/privacy/` 与 `/privacy.html` 返回的是**同一份 HTML**，所以**不能**在 HTML 里加 noindex，否则契约 URL 也会被 noindex。【裁定 R48】`/legal/*` 不加 noindex，也不用 `_headers` 加 `X-Robots-Tag`（代理请求是否继承该头没有文档说明，SEO-05 的备选方案不采用）；重复靠 canonical 消化：它从不被站内链接（D-4 保证），也不进 sitemap。必要时开启实验组 L（`/legal/*/` 单跳 301 到契约 URL），须先通过 M1-03 实测。
- 例外：S0 下的扩展隐私页本身就是 noindex、无 canonical（R2、R49），此时 `/legal/extension-privacy/` 同样如此，没有冲突。
- 站内链接一律写契约 URL。

### 9.2 C-2（兜底：按契约逐个降级）

- `SITE.contractMode` 可写成对象，例如 `{ privacy:'proxy', support:'file', 'extension-privacy':'proxy' }`，只把实测失败的那一个退回 C-2（文档 02 §5.2.1）。
- 降级的契约直接输出 `dist/privacy.html` 等。CF 会自动 308 到无扩展名地址（F24），canonical 改为 `https://www.word-by-word.app/privacy`；`_redirects` 按文档 02 §5.2.3 增量处理：删除该契约的 200 规则和两条变体，新增 `/privacy/ → /privacy 301`。
- 契约 URL 变成单跳 308。iOS 系统浏览器、App Review 和 CWS 都会跟随跳转（研究 09 §3.5），但仍需在下一次提交 App 版本时，把 ASC 的 Privacy/Support URL 更新为最终地址（C2 是 App 级字段，可以随时改，研究 09 §2.1）。

### 9.3 preview 实测脚本与判定标准

build 额外输出 `.cache/contracts.json`：`[{id, public, bare, bareSlash, internal, mode, indexable, experimentL}]`（开关生效后的值）。脚本据此生成断言，不写死 C-1/C-2、S0/S1 与实验组 L 的期望（ENG-03、ENG-13）。

```bash
#!/usr/bin/env bash
# 用法：bash scripts/contract-test.sh <BASE> [--prod]
# 前提：在被部署的同一提交上先执行 node build.mjs（生成 .cache/contracts.json）
set -u; P="${1:?base url}"; PROD="${2:-}"; C="https://www.word-by-word.app"; ok=1; T=$(mktemp)
rows=$(node -e 'for (const c of require("./.cache/contracts.json"))
  console.log([c.id, c.public, c.bare, c.bareSlash, c.internal, c.mode, c.indexable ? 1 : 0, c.experimentL ? 1 : 0].join(" "))')

page() { # $1=URL $2=期望 data-page $3=期望 canonical（空 = S0：必须 noindex 且没有 canonical）
  local h code loc; h=$(curl -s -D - -o "$T" "$1" | tr -d '\r')
  code=$(awk 'NR==1{print $2}' <<<"$h"); loc=$(grep -i '^location:' <<<"$h" | cut -d' ' -f2-)
  [ "$code" = 200 ] && [ -z "$loc" ] || { echo "FAIL $1 → $code $loc"; ok=0; return; }
  grep -q "data-page=\"$2\"" "$T" || { echo "FAIL body $1"; ok=0; }
  if [ -n "$3" ]; then grep -q "<link rel=\"canonical\" href=\"$3\">" "$T" || { echo "FAIL canonical $1"; ok=0; }
  else grep -q 'rel="canonical"' "$T" && { echo "FAIL $1 不应有 canonical（S0，R49）"; ok=0; }
       grep -q '<meta name="robots" content="noindex' "$T" || { echo "FAIL $1 应为 noindex（S0）"; ok=0; }; fi
  if [ "$PROD" = --prod ] && grep -qi '^x-robots-tag:' <<<"$h"; then echo "FAIL $1 生产不应有 X-Robots-Tag（R48）"; ok=0; fi
  echo "  $1 $code $(grep -iE '^(cache-control|x-robots-tag):' <<<"$h" | tr '\n' ' ')"
}
hop() { # $1=源 $2=期望码 $3=期望 Location（绝对）——必须单跳
  local r; r=$(curl -s -o /dev/null -w '%{http_code} %{redirect_url}' "$1")
  [ "$r" = "$2 $3" ] || { echo "FAIL $1 → $r（期望 $2 $3）"; ok=0; }
}
while read -r id pub bare bareSlash int mode idx L; do
  if [ "$mode" = proxy ]; then                                        # C-1（Q01–Q14）
    canon=$([ "$idx" = 1 ] && echo "$C$pub")
    page "$P$pub" "$id" "$canon"; page "$P$pub?from=app" "$id" "$canon"
    [ "$(curl -s -o /dev/null -w '%{http_code}' -I "$P$pub")" = 200 ] || { echo "FAIL HEAD $pub"; ok=0; }
    hop "$P$bare" 301 "$P$pub"; hop "$P$bareSlash" 301 "$P$pub"
    if [ "$L" = 1 ]; then hop "$P$int" 301 "$P$pub"                   # 实验组 L 开：单跳 301
    else page "$P$int" "$id" "$canon"
         cmp -s <(curl -s "$P$pub") <(curl -s "$P$int") || { echo "FAIL $int 与 $pub 内容不一致"; ok=0; }; fi
  else                                                                # C-2：/x.html 单跳 308 → /x
    canon=$([ "$idx" = 1 ] && echo "$C$bare")
    hop "$P$pub" 308 "$P$bare"; page "$P$bare" "$id" "$canon"; hop "$P$bareSlash" 301 "$P$bare"
  fi
done <<<"$rows"
[ $ok = 1 ] && echo "CONTRACT PASS" || { echo "CONTRACT FAIL → 失败的契约在 SITE.contractMode 中改为 'file'（C-2）后重新部署并重测"; exit 1; }
```

| 判定 | 标准 |
|---|---|
| C-1 通过 | proxy 模式的契约 URL（含带 query 与 HEAD 请求）都返回 200、没有 `Location`、`data-page` 正确；canonical 为契约绝对地址（S0 下的扩展隐私页为 noindex、无 canonical）；无扩展名与尾斜杠变体都是单跳 301；实验组 L 关闭时 `/legal/*/` 返回 200、内容与契约 URL 一致 |
| 实验组 L | 开启并重新部署后：契约 URL 仍为 200，`/legal/*/` 单跳 301 到契约 URL，才保留；否则关闭，只靠 canonical（文档 02 §5.4） |
| 逐个切 C-2 | 某个契约任一项失败：只把它在 `SITE.contractMode` 中改为 `'file'`，重新部署后脚本自动按 C-2 断言（`/privacy.html` 单跳 308 到 `/privacy`，`/privacy` 的 canonical 为 `$C/privacy`） |
| 生产复测 | 切换后在 `https://www.word-by-word.app` 上带 `--prod` 再跑一次：契约 URL 与 `/legal/*/` 的响应都**没有** `X-Robots-Tag`（R48）。preview 主机本身带 noindex 头，所以这一项只能在生产域名上验证；iOS 真机打开"设置 → 隐私政策"与订阅页（文档 02 §5.4 上线门槛） |

### 11.4 上线前验收脚本（细化研究 09 §7）：`scripts/verify-deploy.sh`

期望值不写死：脚本读取 build 输出的 `.cache/routes.json`（每条路由的 `id`、`publicUrl`、`indexable`、`contract`、预期 `<link rel="alternate">` 条数、`hreflang`、`script`、`contentLanguage`）与 `.cache/redirects.json`（开关生效后的规则），覆盖 `publish:false` 的 302、`indexHtmlRule`、实验组 C 等配置（文档 02 §5.2.4，ENG-13）。

```bash
#!/usr/bin/env bash
# 用法：verify-deploy.sh <BASE> [--preview|--prod]；前提：同一提交上先执行 node build.mjs
set -u; B="${1:?base}"; MODE="${2:---preview}"; C="https://www.word-by-word.app"; F=0; W=0
QP="${QUERY_PRESERVED:-0}"   # M1-03 实测 _redirects 保留 query 时设为 1，此后 query 丢失判 FAIL
ok(){ printf '  ok   %s\n' "$*"; }; no(){ printf '  FAIL %s\n' "$*"; F=1; }; warn(){ printf '  WARN %s\n' "$*"; W=1; }
st(){ curl -s -o /dev/null -w '%{http_code}' "$1"; }
rd(){ curl -s -o /dev/null -w '%{http_code} %{redirect_url}' "$1"; }
hv(){ curl -sI "$1" | tr -d '\r' | grep -i "^$2:" | head -1 | cut -d' ' -f2-; }
J(){ node -e "const r=require('./.cache/routes.json'), x=require('./.cache/redirects.json'); $1"; }

echo "1) 页面：状态、robots、canonical、hreflang 条数、语言声明（R47、R49、R60）"
while read -r url idx nalt lang script cl; do
  h=$(curl -s "$B$url"); [ "$(st "$B$url")" = 200 ] || no "$url status"
  rb=$(grep -o '<meta name="robots"[^>]*>' <<<"$h")
  if [ "$idx" = 1 ]; then
    grep -q 'content="index' <<<"$rb" && ! grep -qi noindex <<<"$rb" || no "$url robots 应为 index"
    grep -q "<link rel=\"canonical\" href=\"$C$url\">" <<<"$h" || no "$url canonical"
  else
    grep -q 'content="noindex' <<<"$rb" || no "$url 应为 noindex"
    grep -q 'rel="canonical"' <<<"$h" && no "$url 不应有 canonical"
  fi
  grep -qi nofollow <<<"$rb" && no "$url robots 含 nofollow"
  [ "$(grep -o '<link rel="alternate" hreflang=' <<<"$h" | wc -l | tr -d ' ')" = "$nalt" ] || no "$url <link rel=alternate> 条数 ≠ $nalt"
  grep -q "<html lang=\"$lang\"[^>]* data-script=\"$script\"" <<<"$h" || no "$url <html> 语言属性"
  grep -q "<meta http-equiv=\"content-language\" content=\"$cl\">" <<<"$h" || no "$url content-language meta"
  grep -q 'pages.dev' <<<"$h" && no "$url 含 pages.dev"
  [ -z "$(hv "$B$url" content-language)" ] || no "$url 不应有 Content-Language 头"
  [ "$MODE" = --prod ] && [ -n "$(hv "$B$url" x-robots-tag)" ] && no "$url 生产不应有 X-Robots-Tag"
done < <(J 'for (const p of r.filter((p) => !p.contract && p.id !== "404"))
              console.log([p.publicUrl, p.indexable ? 1 : 0, p.alternates, p.hreflang, p.script, p.contentLanguage].join(" "))')
ok pages

echo "2) 契约 URL"; bash "$(dirname "$0")/contract-test.sh" "$B" "$([ "$MODE" = --prod ] && echo --prod)" >/dev/null && ok contract || no contract

echo "3) _redirects：静态规则逐条单跳；query 丢失按 QUERY_PRESERVED 判定（文档 02 §5.3 第 6 条）"
while read -r from to code; do
  r=$(rd "$B$from?utm_source=t")
  case "$r" in
    "$code $B$to?utm_source=t") ;;
    "$code $B$to") if [ "$QP" = 1 ]; then no "$from 丢失 query"; else warn "$from 丢失 query（记入文档 02 §5.3 第 6 条）"; fi ;;
    *) no "$from → $r（期望 $code $B$to）" ;;
  esac
  [ "$(st "$B$to")" = 200 ] || no "$to 非 200"
done < <(J 'for (const q of x.filter((q) => q.code !== 200 && !q.from.includes("*") && !q.from.startsWith("/legal/"))) console.log(q.from, q.to, q.code)')
while read -r from to code; do                                   # splat 规则：各取一个样例，只验首跳（Q19–Q21）
  [ "$(rd "$B$from")" = "$code $B$to" ] || no "splat $from"
done < <(J 'for (const q of x.filter((q) => q.from.endsWith("/*")))
              console.log(q.from.replace("*", "about/"), q.to.includes(":splat") ? q.to.replace(":splat", "about/") : q.to, q.code)')
ok redirects

echo "4) CF 自动行为、大小写、下线内容（Q22–Q30）"
[ "$(rd "$B/ja")" = "308 $B/ja/" ] || no "/ja 尾斜杠"
[ "$(rd "$B/ja/index.html")" = "308 $B/ja/" ] || no "/ja/index.html"
[ "$(rd "$B/chrome-extension")" = "308 $B/chrome-extension/" ] || no "/chrome-extension"
[ "$(st "$B/zh-hans/")" = 200 ] || no "/zh-hans/ 非 200（若为 301，说明匹配不区分大小写，立即关闭实验组 C）"
exp=$(J 'console.log(x.some((q) => q.from === "/zh-Hans/") ? 301 : 404)'); [ "$(st "$B/zh-Hans/")" = "$exp" ] || no "/zh-Hans/ 期望 $exp"
for p in /backup/top.html /README.md /CNAME /img/Screenshot-1.png /wbw_logo.png /css/style.css /js/surfenglish-promo.js \
         /chrome-extension/style.css /chrome-extension/img/hero-screenshot.png /jp/ /definitely-missing-xyz; do
  [ "$(st "$B$p")" = 404 ] || no "$p 应 404"; done
curl -s "$B/definitely-missing-xyz" | grep -q 'data-page="404"' || no "自定义 404"

echo "5) 头部（§3.6.4）"
[[ "$(hv "$B/" cache-control)" == *max-age=0* ]] || no "HTML 缓存"
a=$(curl -s "$B/" | grep -oE '/assets/site\.[0-9a-f]{12}\.css' | head -1)
[ "$(hv "$B$a" cache-control)" = "public, max-age=31536000, immutable" ] || no "指纹资源 Cache-Control 不是单一 immutable 值（疑似被拼接）"
[ "$(hv "$B/" x-content-type-options)" = nosniff ] || no "nosniff"
if [ "$MODE" = --prod ]; then
  [ "$(hv "$B/" server)" = cloudflare ] || no "server 非 cloudflare"
  [[ "$(rd "http://${B#https://}/")" =~ ^30[178]\ https:// ]] || no "http→https"
else
  [[ "$(hv "$B/" x-robots-tag)" == *noindex* ]] || no "预览应带 X-Robots-Tag: noindex"
fi

echo "6) sitemap / robots / GA"
sm=$(curl -s "$B/sitemap.xml")
[ "$(grep -o '<loc>' <<<"$sm" | wc -l | tr -d ' ')" = "$(J 'console.log(r.filter((p) => p.indexable).length)')" ] || no "sitemap 条数"
while read -r u; do grep -q "<loc>$C$u</loc>" <<<"$sm" || no "sitemap 缺 $u"; done < <(J 'r.filter((p) => p.indexable).forEach((p) => console.log(p.publicUrl))')
while read -r u; do grep -q "<loc>$C$u</loc>" <<<"$sm" && no "sitemap 含 noindex 页 $u"; done < <(J 'r.filter((p) => !p.indexable).forEach((p) => console.log(p.publicUrl))')
curl -s "$B/robots.txt" | grep -q "Sitemap: $C/sitemap.xml" || no robots
curl -s "$B/" | grep -q 'G-QS1CJY8YWL' || no "GA 缺失"
[ $F = 0 ] && { [ $W = 0 ] && echo "ALL PASS" || echo "PASS WITH WARNINGS"; } || { echo "FAILED"; exit 1; }
```

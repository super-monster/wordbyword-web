## 0. 摘要

1. 【决策】一句话概念：**整个官网排成"一页被 WordByWord 批注过的读物"**。视觉元素只取产品自己的批注语汇：3px 红色译文引用条、`#FEE437` 荧光笔、语块下划线、logo 速度线、4 阶红黑马赛克。每种母题只在产品里有同样含义的地方出现：红条只挂在"译文/回答"下面，荧光笔只标 hero H1 的一个短语和样张里被查的词（R65、VIS-02、VIS-20）。
2. 【决策】颜色只有"纸、墨、红阶、黄"四组。系统蓝 `#007AFF` 只出现在机身复刻图内部（§2.1）。所有文字配色都过 WCAG AA（§2.4）。小字号红色文字统一用 `#B32847`，因为 `#CC3355` 在 `--paper-2` 上只有 4.36:1。
3. 【决策】零 webfont。按 `:lang()` 分语言写系统字体栈，页面内带 `lang` 的外语片段也切换到对应字体（I18-08）；另配一套衬线"阅读"栈（拉丁、西里尔、中日韩；vi 跳过缺越南语字母的 Iowan，I18-09）。断行：ja 标题用 `keep-all` 加 locale JSON 中的 `{wbr}` 记号（R61），zh 标题用 `text-wrap: balance`，不用 `｜` 作标记（§3.5）。
4. 【裁定 R68】字号阶梯重定：section H2 44px、L 级功能 H3 32px、M 卡 H3 22px，三级之间约 1.37 倍；分区间距"一个 token，不相加"，桌面 96px、手机 56px（§3.2、§4.2）。
5. 【决策】首页版式分 L / M / S 三级：2 个大段（右滑翻译、双击查词"批注跨页"）、4 张中卡（X、语块/Action Flow、朗读、句法）、1 张排版式"规格清单"（取代 4 列图标栅格，VIS-07），再接截图画廊。取消轮播、AI 插画图标和全站滚动渐入动画（§4.3）。
6. 【裁定 R66、R69】Hero 是 HTML/CSS 实时双语样张，按 402×874pt 复刻 App 内置浏览器。样张里是一篇自写的完整短文（标题、署名行、被翻译的段落、未翻译的后续段落），不再用灰色骨架条。手机首屏顺序为 H1 → 定义句 → CTA（含"免费下载 · iPhone & iPad"）→ 样张，390×844 首屏内能看到红色译文条（§5.2）。
7. 【裁定 R67】截图一律裁到"只剩屏幕"并**裁掉原始状态栏**，由 CSS 机身统一画 9:41 状态栏；图片里不带框，框永远由 CSS 画，机身不加投影（§5.3、§7.1）。
8. 【裁定 R71】"读 X"卡在全部 20 个 locale 都用 HTML/CSS 通用社交帖样张（自写文本、虚构账号、无 X 标志）。en 的 NHK 截图在 16:9 节选里无法避开 "Extract chunks" 按钮，因此也不用（§5.4.3）。
9. 【裁定 R10、R11、R43、R44】SurfEnglish 卡片放在价格区之后、FAQ 之前：WBW 纸面卡片里只开一扇 SE 深色"窗口"，配图是 SE 官网 `games-home.jpg` 的上部裁切（游戏页，内容中性）；不用黑色 App Store 徽章，只用文字链接；SE 图标 32px。桌面 ≤ 420px、手机 ≤ 480px（≥ 375px 视口；320px 下 ≤ 560px，R84）；zh-Hans 页不渲染该卡（R42）。WBW 的最终 CTA 加强为"80px App 图标 + 64px 马赛克 + H2 + 要点回顾 + 徽章"（§5.9、§5.10）。
10. 【裁定 R43、R68】价格区只有"一张表 + 一行说明 + WBW App Store 徽章"，删除 Free/Plus 两张复述卡；价格写进 Plus 列表头。languages 用便签底，pricing 改回纸面底，二者交替（§5.7）。
11. 【决策】素材：en、ja、zh-Hans 使用本地化截图，其余 17 个 locale（含 zh-Hant，R33）回落到 en 截图。本机与原型实测：屏幕图 AVIF 720w 约 50–75 KB，16:9 节选约 13–22 KB，SE 窗口 400w 7.9 KB。首页 DPR2 整页图片约 0.26 MB，首屏位图约 4 KB（§8.3）。
12. 【事实】素材管线已在本机实测：`sips` 负责解码与 Display P3 → sRGB、缩放、AVIF/JPEG/ICO 编码；**精确裁切在 node 中完成**（`sips` 的 crop 在偏移 0 0 与裁切框贴底时会静默出错，R79、原型 G6）；AVIF 宽高必须为偶数（R8、K1）。脚本名与目录按文档 06 §7（`scripts/images.mjs`、`scripts/images.manifest.json`），裁切坐标与质量参数按本文 §7（R8）。

## 1. 设计理念

### 1.1 概念

**"纸与墨 · 阅读批注"**（基线 §E）：官网就是一页外语读物，WordByWord 在上面做了批注。原文印在暖白纸上，译文挂在红色引用条后面，被查的词用荧光笔标出，语块下面画了线，页边写着编号注释。

### 1.2 为什么属于 WordByWord：母题与出处

| 母题 | 产品中的出处【事实】 | 在官网中的用法【决策】 |

### 1.3 与 SurfEnglish 的家族关系

| 维度 | WordByWord：纸与墨 | SurfEnglish：深海玻璃（研究 03 §3） | 共享的部分 |
|---|---|---|---|
| 明暗 | 亮色为主，暗色跟随系统 | 只有暗色（`style.css` 中无 `prefers-color-scheme`） | token 命名架构（`--ink/--hairline/--accent`） |
| 底色 | 暖纸 `#FBF8F3`，实色 | `#04060D` 叠 5 层径向光斑 | — |
| 强调色 | `#CC3355` 单色相 4 阶，实色、不用渐变 | 青 `#4FD2FF` → 紫 `#B388FF` 渐变 | **红色译文引用条**：SE App 内同为 `#CC3355`，SE 官网 `--quote` 为 `#FF5C8A` |
| 材质 | 平面、细线、马赛克，无 `backdrop-filter`，机身无投影 | 玻璃模糊 22px、光晕 | — |
| 圆角 | 4 / 8 / 14 | 16 / 26 | 胶囊仅用于语言标签 |
| 字体 | 系统无衬线 UI + 衬线阅读 | 全部无衬线 | 系统字体栈，零 webfont |
| 标题层级 | 字号阶梯 + 编号 eyebrow；荧光笔只在 hero H1 | `.kw` 渐变下划线 | 两者的标注都取自各自产品 |
| Hero 样张 | 内置浏览器里的一篇亮色网页文章 | 新闻信息流（暗色） | 都用 `--pt` 等比复刻，都有 `is-static` 终态 |
| 动效 | 只有样张和批注引线有动效 | reveal、voice-wave、样张 | 都受 reduced-motion 守卫 |
| 容器 / 断点 | 1120；560 / 900 / 1200 | 1120；560 / 900 | 同一套栅格手感 |
| header | 实色纸面，sticky | 玻璃，sticky | `<details>` 语言菜单 |

【决策】家族感来自 4 样共享的东西：组件语法、红色引用条、两枚"单色相 4 阶几何"图标在页脚并列、SE 窗口在 WBW 站内保留原貌。性格差异则靠明暗、材质和几何体现。**不 fork SE 的 `style.css`**（研究 03 §3.8：直接 fork 会同时"像 SE 换皮"和"仍然千篇一律"）。


补充细节：tr 页依赖 `<html lang="tr">` 让 `uppercase` 正确产出 `İ`；vi 的大写叠加变音符时，eyebrow 行高设为 1.4，避免被裁切。

### 3.4 段落与标题的通用规则

`h1,h2,h3 { text-wrap: balance; }`，`p, li { text-wrap: pretty; }`，正文 `max-inline-size: var(--w-text)`；数字列使用 `font-variant-numeric: tabular-nums`；链接正文中**始终带下划线**（`text-underline-offset: .18em; text-decoration-thickness: 1px`，hover 时 2px），不只靠颜色区分（WCAG 1.4.1）。

### 3.5 CJK 断行策略【裁定 R61；I18-03】

v1.0 用 `｜` 作断行标记，与文档 03 规定的 CJK title 分隔符 `｜` 冲突：构建若把 locale JSON 里的 `｜` 一律转 `<wbr>` 或剥离，ja/zh 的 `<title>` 和 JSON-LD `name` 会变成「WordByWordiPhoneでWebページ…」，而 seoLint 的 `startsWith(brand)` 检查照样通过。v1.1 改为专用记号 `{wbr}`。

| 场景 | 规则 |
|---|---|
| 记号 | locale JSON 中写 `{wbr}`（ASCII，不会与任何语言的正文字符冲突）。构建只在**标题类 kwtext 字段**里把它转成 `<wbr>`：`hero.title`、`featuresIntro.title`、`features[].title`、`gallery.title`、`languages.title`、`pricing.title`、`sibling.card.title`、`faq.title`、`cta.title`、按钮文字。在 `<title>`、meta、OG、JSON-LD、`alt`、`aria-label` 以及 `plain()` 输出中一律剥除。文档 06 §3.7 的 L-7 校验：`{wbr}` 只允许出现在上述字段（且只用于 CJK locale），出现在别处报 E；标题类字段中出现全角 `｜` 也报 E |
| ja 标题（H1–H3、按钮） | `word-break: keep-all; overflow-wrap: anywhere;` 加 `{wbr}` 断点。原型 D16 在 `render.mjs:58-67` 手工补的 ja 断点（以 `｜` 写成）需要改写成 `{wbr}` 回写进文档 08 §3；去掉记号后必须与 08 原文逐字相同 |
| ja 渐进增强 | `html:lang(ja) :is(h1,h2,h3):not(:has(wbr)) { word-break: auto-phrase; }`，仅 Chromium 119+ 生效，写在 `keep-all` 之后；不支持的浏览器仍走 `<wbr>`。【M2 审计修正 C11】auto-phrase 会覆盖 `{wbr}` 断点（Chrome 中出现「WordByWordに⏎ついて」），因此只用于没有标记的标题 |
| zh-Hans / zh-Hant 标题 | `word-break: normal; text-wrap: balance;`，**不做人工标注**：中文排版本来允许字间断行，balance 已能避免孤字行（I18-03 方案 ②）。如 A7 巡检发现个别标题断得难看，再给该字段加 `{wbr}` 并在该元素上切换为 `keep-all`（`.wbr-keep`）。【M2 实现】用 `:is(h1,h2,h3):has(wbr)` 自动切换，不另加 class；M2-11 巡检后 zh-Hans 的 H1、H2 与长 H3 已加 `{wbr}`（如 "原文不／动""网页翻／译"在 375 与 1280 宽下都断在词中） |
| ja / zh 正文 | `line-break: strict`（避头尾），`word-break: normal`；`overflow-wrap: anywhere` 只在 URL、长英文串的容器上使用 |
| ko | 全站 `word-break: keep-all`（韩文以空格分词，避免词中断开）；不使用 `{wbr}` |
| th | 不改 `word-break`，交给浏览器 ICU 词典断行。标题中确需不断开的复合词，在 JSON 中用 U+2060 连接（SE `promo/README.md` 用的是同一做法） |
| 构建校验 | **只对 ja**：H1 每段（两个 `{wbr}` 之间）≤ 10 个字，超长报 warning。ko、zh 不做段长校验（v1.0 对 ko 会恒报 warning） |
| 备选（未采纳） | 在 `tools/` 下 vendor BudouX 的 ja 模型 JSON（Apache-2.0，不引入 npm 依赖），构建时自动插入 `<wbr>`。当 ja 的人工标注成本过高时再启用；本期按 R61 用人工 `{wbr}` |

文档 07 M2 需要为"`{wbr}` 记号的转换、剥除与 L-7 校验，以及 ja 标注回写"增加 0.5 人日（I18-03 ⑤，由文档 07 落实）。

### 4.2 分区间距【裁定 R68；VIS-06】

```css
.section--band      { padding-block-end: var(--sy, var(--section-y-m)); }
.section--band      { background: var(--paper-2); }
```

#### 5.2.4 动效时间线【原型 D15】

页面加载时显示服务端输出的终态 `is-static`，循环从终态开始，因此不会闪一下，无 JS 时的画面与有 JS 时的起点一致。

| 时间（ms，自进入视口起） | 状态类 | 视觉 |
|---|---|---|
| 0 | `is-static` | 终态：译文已展开、单词已高亮、卡片可见、提示物隐藏。进入视口（IntersectionObserver threshold .35）后开始计时 |
| 1200 | `is-idle` | 卡片和高亮淡出，译文收起（500ms） |
| 1800 | `is-swiping` | 触点（白色圆点 + 速度线拖尾）在 `.s1` 起点出现，900ms 内**从左向右**移动 140pt（`--ease-swipe`）；原句同步右移 8pt 后回弹；出现标签 `cue-label`（`demo.ui.swipeCue`）。**任何 locale（含 ar）都不镜像**（R63） |
| 2700 | `is-translated` | `.wb-tr-wrap` 的 `grid-template-rows` 从 0fr 变为 1fr（`--dur-4`）；红条 `scaleY 0→1`，`transform-origin: top`，`--dur-3` |
| 4200 | `is-tapping` | 在 `.w` 上出现两圈涟漪（间隔 180ms，直径 10→44pt） |
| 4800 | `is-lookup` | `.w` 变为荧光笔高亮（`--dur-2`）；卡片 `translateY(24pt)→0` 加淡入（`--dur-3 --ease-out`） |
| 8200 | 循环 | 回到 `is-idle` 再播一轮；播完 `data-loops` 次（默认 2）后停在 `is-static`，按钮变为"重播" |

- 【决策】无 JS、`prefers-reduced-motion: reduce`、用户点"暂停"这三种情况都停在 `is-static`。
- JS（≤ 3 KB，并入 `main.js`）：`ResizeObserver` 把 `.cue-tap` 和卡片箭头锚定到 `.w` 的 `offsetLeft/Top`；`document.fonts.ready` 后重新计算位置；`visibilitychange` 时暂停。以上对标 SE `main.js:36-52`，但代码重写，不复制。
- 【决策】暂停按钮始终可见（44×44 热区，文字按钮）：循环演示总时长超过 5 秒，又与其他内容同屏，按 WCAG 2.2.2 必须提供暂停。

#### 5.2.6 RTL、暗色与可访问性【裁定 R63；I18-01、I18-05】

- **RTL（ar）**：机身外部按逻辑属性镜像。机身内部：`.device-screen` 恒为 `dir="ltr"`；页面原文（英语）保持 LTR；译文块 `.wb-tr[lang=ar]` 设 `dir="rtl"` 加 `text-align: right`，保留物理左侧的红条和左内边距；查词卡 `.wb-card` 设 `dir="rtl"`（卡片语言是阿语）；图注加一句"阿拉伯语译文按从右到左排版"。
  - 【事实】App 的译文 span 只有 `lang`、没有 `dir`（`10-dom-render.js:1138` 的 `wbw_generateHtml`），真实 App 里阿语译文以 LTR 为基向、左对齐，句末标点会跑到错误的一端。网站样张按正确的 RTL 排版并在图注中注明；该问题登记为 App 侧改进项（建议 `.wbw-t-translated` 加 `dir="auto"`，§11）。
  - **手势方向不镜像**：App 按物理方向判定右滑（`20-features.js:418` `distanceX > 0` 走翻译，`:487-501` `distanceX < 0` 移除译文），App 自己的阿语提示是「اسحب لليمين」。所以 `.cue-swipe` 触点和速度线拖尾在 ar 页也**从左向右**移动；ar 的 `demo.ui.swipeCue` 写"向右滑"（文档 03 §2.3、文档 08 §7.3/§7.7 同步）。
- **暗色**：机身屏幕**始终是亮色网页**（`--screen-*` 不随主题变），与真实截图一致；机身边框随主题切换（`--device-bezel`）。
- **可访问性**：状态栏、地址栏、署名行、后续段落、工具栏、提示物都加 `aria-hidden`；文章标题、被翻译的原文、译文、卡片是可读的真实文本，带 `lang`，可被索引（容器带 `data-nosnippet`，文档 03 §3.6）。`<figcaption>` 写明"HTML 演示，非截图"，这也是诚实披露。

## 7. 素材使用总表

### 7.1 统一处理管线【事实：本机已逐步实测；裁定 R8、R58、R67、R79】

分工（R8）：**裁切坐标、质量参数、CSS 机身**以本文为准；**脚本名、目录、指纹路径**以文档 06 §7 为准——`scripts/images.mjs` 读取 `scripts/images.manifest.json`，产物写入 `assets/img/<group>/<set>/<subject>-<w>.<ext>` 并生成 `assets/img/images.json`，构建时指纹化为 `/assets/img/…<h8>.<ext>`。原型 `prototype/tools/build-images.mjs` 是参考实现（v1.0 写的 `tools/images/build-images.mjs`、`public/images/…` 路径作废）。

```
源图 ─(1) sips 解码为 PNG + Display P3 → sRGB ─▶ (2) node 屏幕裁切（去状态栏）/ 节选 ─▶ (3) sips 缩放为中间 PNG
     ─▶ (4) node 裁成偶数宽高 ─▶ (5) sips 编码 AVIF + JPEG ─▶ (6) 结构检查 + Chrome 解码 alpha 校验（check-images.mjs）
     ─▶ assets/img/…（提交入库）
```

【裁定 R79】**裁切在 node 中完成**（解码 PNG → 按裁切框逐行拷贝 → 编码 PNG，参照原型 `tools/png.mjs` 与 `build-images.mjs` 的 `cropSRGB()`，并断言裁切框在图内）；`sips` 只做解码与色彩转换、缩放、格式编码。【事实，原型 README G6】本机实测 `sips -c … --cropOffset` 在偏移为 `0 0` 时退回居中裁切、裁切框贴着底边时（如 `raw` 去状态栏 0,162 1206×2460）直接返回原图，都不报错。实现细节见文档 06 §7.2。

| preset | 适用源 | 整屏区（x, y, w×h） | **去状态栏后的裁切区**（R67） | 依据 |
|---|---|---|---|---|
| `demo` | `WEB/img/en/*_demo.png`、`more_definitions.png`（1530×3036，透明带框） | 122, 120, 1286×2795 | **122, 293, 1286×2622** | 像素扫描：x122 处由暗变亮，y120 进入屏幕；状态栏 54/874 × 2795 ≈ 173px |
| `marketing` | `RES/wbw_*/*.00N.png`、`zh-右滑翻译.png`（1284×2778） | 221, 819, 842×1830 | **221, 932, 842×1717** | 机身 bbox 为 x182–1101、y786–2681；状态栏 ≈ 113px |
| `raw` | 原始截图 1206×2622（`スクリーンショット*`、`*_en.PNG`） | 0, 0, 1206×2622 | **0, 162, 1206×2460** | 原图即屏幕；状态栏 162px |

- 去状态栏后三种 preset 的宽高比都是 0.490（402:820），统一输出 **720×1468**（另有 540×1100、360×734 档），由 CSS 补 54pt 状态栏（§5.3）。本机像素扫描确认 54pt 处落在空白带内：内置浏览器截图的 0.052–0.080 屏高、弹层截图的 0.045–0.071 屏高都是纯色行，裁切不会切到地址栏或弹层把手。
- 【事实，R8、K1】sips 遇到边长超过 1024px 的 AVIF 会写成 512px 分块的 grid；Chrome（libavif）渲染宽或高为奇数的 4:2:0 grid AVIF 时整张图**全透明**。所以第 (3)(4) 步先缩放成 PNG，再裁成偶数宽高后编码。第 (6) 步按 R79（修正 R58）：闸门 = **结构检查**（零依赖解析 AVIF，偶数宽高、是否为 512px 分块 grid）+ **Chrome headless 实际解码后的 alpha 抽样**（透明像素占比超过阈值即失败）；`sips -s format png` 回解只作辅助，不作闸门，因为 sips/ImageIO 复现不了 Chrome 的白板问题（原型 G5：坏图 sips 回解 1.69% 透明、Chrome 回解 100% 透明）。见 `scripts/check-images.mjs`、文档 06 §7.5。
- 【事实】`RES` 下的营销图和原始截图都带 **Display P3** 配置文件（`sips -g profile`），`img/en/*_demo.png` 没有配置文件。必须统一转为 sRGB，否则截图里的 `#CC3355` 引用条会与页面 CSS 的红出现色差。
- 质量参数：屏幕图、节选 AVIF q45 + JPEG q60；SE 窗口 AVIF q50 + JPEG q60。【事实】AVIF q45、720w 时日文小字清晰（已解码目视）；q45 比 q60 小 15–18%。
- **坐标约定**：节选 `region.y`、编号钉 `pins[].y`、描边环 `ring` 都用**整屏（402×874pt，含状态栏）比例**记录，与语言无关，也与 CSS 机身屏幕（同样是 402×874）一一对应。源像素换算：`y_px = 整屏区.y + round(y × 整屏区.h)`，节选高 `round(0.259 × 整屏区.h)`（16:9）。节选与钉位的 `y` 不小于 0.07，避开状态栏。
- **节选的上下边必须落在空白行**（VIS-10）：下表的 `y` 已在本机逐张扫描（每行亮度标准差 < 4 视为空白）并目视复核。【M2-09 实现修正】`images.mjs` 与 `check-images.mjs` 的门槛改为节选首末 4px 行的**墨迹占比 ≤ 0.5%**（原型 G4 的 `inkShare`），标准差 ≥ 4 只打印提示：空白行若横跨白底与浅灰卡片的交界，σ 可达 5–6，但其中并无文字。
- `statusBg` / `statusTone`：取裁切图首行像素（即 55/874 屏高处）的颜色，可在 manifest 手动覆盖。本机采样：内置浏览器截图为 `#F3F3F4`（深色字）；弹层、详情页截图为 `#000000`（白字）；`zh-双击.001.png`（App 处于暗色模式）为 `#0E0E0E`（白字）。

### 8.2 标记模板

```html
<div class="device device--l" style="--status-bg:#F3F3F4">
  <div class="device-screen">
    <div class="ios-status" data-tone="dark" aria-hidden="true">…</div>
    <picture>
      <source type="image/avif"
              srcset="/assets/img/shot/ja/lookup-360.a1b2c3d4.avif 360w, /assets/img/shot/ja/lookup-540.d4e5f6a7.avif 540w, /assets/img/shot/ja/lookup-720.g7h8i9j0.avif 720w"
              sizes="(min-width: 900px) 340px, min(315px, 80vw)">
      <img src="/assets/img/shot/ja/lookup-540.j0k1l2m3.jpg" width="540" height="1100"
           alt="（功能描述，见 §9.4）" loading="lazy" decoding="async">
    </picture>
  </div>
</div>
```

- 每个 `<img>` 都写 `width`/`height`（取 `<img src>` 那一档的固有尺寸，CSS 用 `inline-size:100%; block-size:auto`），这是验收项。路径与指纹格式按文档 06 §3.5（`/assets/img/<group>/<set>/<subject>-<w>.<h8>.<ext>`），模板只能通过 `img(key)` 引用。
- `loading="lazy"`：首屏以外全部加。hero 区没有位图，因此首页没有图片需要 `fetchpriority="high"`。例外是 Chrome 页的 hero 截图：它用 `loading="eager" fetchpriority="high"`，并且是该页的 LCP 候选（研究 06 §6.1：LCP 图片不能懒加载）。
- JPEG 回退只出一个中间档，作为 `<img src>`，回退文件数量因此减半。不支持 AVIF 的浏览器（Safari < 16.4）拿到的是 540w JPEG。
- **透明图处理**：屏幕裁切后已没有透明区，可以直接出 JPEG（屏幕四角由 CSS 圆角裁掉）。Chrome 三条局部图原本带 alpha，但实际内容是白底，回退时压平到 `#FFFFFF` 出 JPEG。只有图标保留 PNG 透明。
- 文件名与缓存：描述性的英文短名 + 宽度 + 构建期内容指纹（基线 §D）；`_headers` 为 `/assets/*` 设置 `max-age=31536000, immutable`（文档 06 §3.6.4）。favicon（含暗色版）与 `apple-touch-icon.png` 放在固定根路径，不加指纹，使用短缓存。
- 本机没有 WebP 工具（F33），**不出 WebP**。AVIF 加 JPEG 已覆盖全部目标浏览器。

## 9. 暗色模式、RTL、动效、可访问性

### 9.1 暗色模式【裁定 R70；VIS-13、VIS-21】

- 只跟随 `prefers-color-scheme`，token 见 §2.1。截图不加滤镜，也不调暗；机身边框和 hairline 负责把亮截图与暗底分开。
- **App 图标描边**：App 图标 16 格中有 10 格是黑色和 `#44111C`，对暗色页面底只有 1.11:1 / 1.21:1，轮廓会消失（VIS-13，en-D-00 的 header、en-D-09 的页脚）。暗色下所有 WBW 图标加 1px 浅色外圈，保留 22.4% 圆角：

```css
.brand-icon, .family-mark img, .cta-icon { border-radius: 22.4%; box-shadow: 0 0 0 1px var(--icon-ring); }
/* --icon-ring：亮色 transparent；暗色 rgb(242 236 230 / .40)，合成色 #6C6866，对 --paper 3.44:1（§2.4） */
```

  favicon 另出暗色版（§7.8）；`apple-touch-icon` 不变（iOS 主屏不在暗色页面上显示）。
- **荧光笔**：暗色下 `--marker` 改为 `#D8BE2A`（墨字在其上 9.75:1，色块对底 10.22:1），避免 `#FEE437` 在近黑底上 14.78:1 的刺眼大色块。样张与截图内的查词高亮仍为 App 原值 `#FEE437`。
- **红色**分两种用法：作条和按钮底时仍用 `#CC3355`，作文字时用 `#F27891`。
- **固定为亮色"屏幕"的组件**：hero 样张、X 样张、语块示意卡都用 `--screen-*`，两种主题下不变，与 M 网格里的两张截图节选保持一致（VIS-21：v1.0 的语块卡随主题变暗，2×2 网格在暗色下呈"三白一黑"）。SE 窗口本来就是暗色截图，也不变。
- **标签**：`.tag--en-only` 暗色下改为透明底加 1px `--hairline-strong` 边框（§5.12）。
- **马赛克**：K 格改用 `--mosaic-k`（`#2E2826`），保留格子感（§5.13）。

### 9.3 动效原则

1. 动效只在两处出现：hero 样张（讲清右滑和双击）、L2 引线（只播一次）。其余交互只有 `--dur-1` 的颜色和下划线过渡。
2. 不做滚动渐入、视差、自动轮播或持续的装饰动画（R7）。
3. `@media (prefers-reduced-motion: reduce)`：关闭所有 animation 和 transition，`scroll-behavior: auto`；样张停在 `is-static`，提示物隐藏。
4. 页面不可见时暂停（`visibilitychange`）；样张最多播放 2 轮。
5. 只对 `transform`、`opacity`、`grid-template-rows` 做动画，不对 `top`、`left` 等触发布局的属性做动画。

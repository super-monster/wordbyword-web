## 0. 摘要

1. 【决策】分 7 个里程碑 M0–M6。v1.1 吸收评审与裁定后，Phase 1 上线前开发者投入：**人工估时 43.05 人日**（v1.0 为 35.9；v1.1 新增的 6.4 人日来自 ENG-10/11/12、I18-03/05/06、R36、R52、R58 等；v1.3 再加 0.75：M2-15 文案键补齐 0.5（R77、R78），M3-06 中 en 通读与双模型互检 0.25（R80）），**AI 辅助（Claude Code）估时约 24.5 人日**，排期按 AI 辅助 ×1.3 ≈ 32 人日。外部母语审校：上线前 1.0 人日（ko；en 按 R80 不设外部审校），上线后 3.75 人日（T2、T3）。上线后收尾约 3.85 人日；Phase 2 人工约 11 人日（AI 辅助约 6.9）。文档 06 §12.1 的 25.0 人日（v1.0 为 20.5）只算工程，不含本地化、QA 和审校。
2. 【裁定】T0 目标窗口 2026-11-17～11-26，预期 **2026-11-25**（R23）。乐观 11-17，保守 12-08。如果 AI 辅助的压缩没有兑现、又遇到保守条件，T0 会越过 12-17，届时改到 2027-01-12 那一周（§4.2、§4.3）。M1 结束时按实际投入校准一次（§4.2）。
3. 【裁定】开工第一步是 M0-02：从 `7a389ba` 建 `legacy-pages`，把 GitHub Pages 发布源切过去（R29）。验收按 R56 比对关键 URL 切换前后的状态码与响应体 md5，**不用 last-modified**：GitHub Pages 每次部署都会把 Last-Modified/ETag 改成部署时间（ENG-01）。切换前不得往 main 推送任何重构提交。`docs/`、`prototype/` 默认不入公开仓库（R30、H10）。
4. 【决策】M1 第 2–3 天先做 CF preview 实测 spike，一次关闭 10 个【需实测】项，定下 `contractMode` 与 `redirectFlags`，之后再写其余代码（M1-03）。`_redirects` 以文档 02 §5.2 为唯一规格，默认 **67 条静态、7 条动态**（R54，文档 02 §5.2.3）。
5. 关键路径：冻结 legacy → 生成器骨架 → CSS 与模板 → en 全部模板完成后冻结 `strings-v1`（R59）→ T1/T2/T3 初稿 → T1 审校（本人 zh-Hans/zh-Hant/ja + en 通读，外部 ko）→ 17 个 locale 的 OG → QA → T0。母语审校按 R36 有默认分工，不再是无默认值的阻塞项；ko 若在 T-7 前没有外部审校，按"双模型互检 + 回译 + 术语表 lint"上线并标记待复核；en 按 R80 由本人通读 + 双模型互检后上线，不设外部审校前置，不阻塞 T0。
6. 风险登记共 29 条（§5，RK01–RK29），覆盖任务要求的 13 类。最需要盯的 5 条：RK02 契约 URL、RK06 main 重建冲掉线上旧站、RK10/RK11 翻译质量与审校资源、RK04 DNS 切换、RK14 AVIF 全透明缺陷（原型已复现）。
7. Runbook 分 T-7 / T-1 / T0 / T+1h / T+1d / T+7d 六个时间点（§6），另有应急公告与热修路径（§6.8，R57：从生产分支拉 hotfix，不从 main 直接部署）。回滚分两层：CF 部署回滚，或把 DNS 改回 GitHub。**DNS 回滚截止日 = T0 当时 GitHub 证书的 notAfter**（R23），不是固定的 12-23。
8. 【裁定】KPI 口径按 R18、R50：`wordbyword` 28 天平均排名 ≤ 2.0，7 日均值连续 7 天 > 3.0 为警戒；品牌桶点击 ≥ 基线 80%；非品牌 = 未筛选总量 − 品牌正则匹配量；删除"全站点击 ≥ 57"；点击类告警须连续两个 28 天窗口不达标才触发。ASC Marketing URL 只算发现与引荐入口（nofollow）；真正 follow 的按 locale 外链是 SE 页脚 PR-SE-2，须在 T+7d 内合并，PR-SE-1 在 T0 前合并（R51）。
9. 待用户提供（§8）直接引用裁定第三节 H1–H18。没有默认值、会阻塞里程碑的只有 2 项：H9 CF 权限（M1）、H8 DNS 与 GSC 权限（M5）；H2 须在 T-7 前导出。
10. v1.0 §10 列出的 24 处冲突和 3 项同步事项已全部由 R1–R28 裁定，§10 改为"已裁定（R#）"结论表。本次修订另发现 3 处待同步问题（§10.1），其中需主控决定的 en 审校默认值已由 R80 裁定（N3），sips 校验的字面要求已由 R79 修正（N2）。

### 4.3 回滚期限与上线窗口规则【裁定，R23】

- 【事实】现在的 GitHub 证书由 Let's Encrypt 签发，有效期 2026-09-24 至 12-23（`openssl s_client` 实测，F6）。切到 CF 之后，GitHub 无法再续签。
- 【推断】GitHub 大约在到期前 30 天（约 11-23）续签。因此 **DNS 回滚截止日 = T0 当时生效证书的 notAfter**。T0 在续签之前，截止日是 12-23；在续签之后，截止日约为 2027-02 下旬。文档 06 §10.4 已按 R23 写为"T0 当时证书的 notAfter"（T-1 实测记录），不再写固定期限。
- 规则：T-1 时记录 notAfter。如果 notAfter − T0 < 21 天，就二选一：① 推迟 T0，等 notBefore 变化（说明已续签）后再切；② 按研究 09 §3.10 做双托管热备（约 1 人日）。
- 避开 12-18～01-04：T+1d 至 T+7d 需要开发者在岗。如果 T0 会越过 12-17，就改到 2027-01-12 那一周。

### 4.5 AI 辅助（Claude Code）估时规则【新增，R23】

### 6.8 应急公告与热修（R57）

公告和生产热修一律从生产分支出发，**不得从 main 直接部署到生产**：main 上可能有还没经过 Go 的改动。

5. 关闭公告走同样的流程。
